## 信任边界与剩余门禁

F-01 只冻结明确识别并批准的入口及所列材料，不冻结所有 import、动态模块、脚本内部依赖或 DLL。动态命令仍可以本机明确批准；cwd/Job Object 不构成主机文件系统或网络沙箱。当前单次审批是产品阶段选择，本轮不实现工作会话/ConPTY，也不把未来连续授权固定为逐命令人工批准。

F-02 成功撤销仅保证新的线程恢复不能继续用已撤销许可；已 running 的停止与树清理必须另查询。BUSY 是失败，disable 部分失效后 BUSY 不是全部成功。

F-03 Native 可变快照检查后必须释放句柄，至 Resume 和 Git 执行仍有外部窗口；commit 的 tree/parent/CAS 是独立保护，switch/pull 的拒绝与 postcondition 不是完整跨进程 Git 事务。发生失败或不确定结果必须人工复核；不自动回滚用户数据。HTTPS remote 写入后断流已实证，unknown 不可被重试/归档误当作成功。

扩展 pull 实测：index=GIT_STATE_CHANGED；外部 HEAD 变化=interrupted/HELPER_CLEANUP_UNCONFIRMED，不能据此宣称拒绝任务的清理已确认；refs 变化=GIT_POSTCONDITION_UNTRUSTED。三者外部进程 exit=0，用户 fixture 数据保留，新写请求拒绝，结果不确定记录仍保留。

F-05 活动容量可持续使用，历史总磁盘量仍增长；全部为活动/不确定任务时保守满额拒绝。自动档案保留期、磁盘监测与结果不确定任务的人工处置是独立运维设计，不以随意删除未知记录解决。

开发分支修复等待独立审查者复审，特别复查启动许可的成功/BUSY 线性化、固定 commit/ref CAS、hold 与归档重启路径，以及上述 F-04/06 限定 Beta 范围。Elevated Token 验收仍缺。不得据本报告宣布 Production 安全通过。
