# V1.3 F-03 外部 Git 并发证据

基线：948a0dc068e87eff0e06f1ff1d31635570bca0c3。本轮先精确复现，再修复证实的缺口。

## 修前发现

第二个真实 Git 进程在计划重算后或 Native suspended 时改变 index、refs、HEAD/worktree。原实现的 commit 实际提交了计划外 external-index.txt；外部 refs/heads/main 推进后，原 commit 使用外部 parent，并生成缺少外部 ref 数据的 tree，仍 reported success。冲突 dirty switch 由 Git 自身拒绝并保留 marker。C2C 自有仓库锁不能阻止外部 Git。

## 最小修复

- protected state 下私有 index 副本计算批准 tree，不修改实时 index cache。
- 固定内部 commit 入口使用 commit-tree <tree> -p <parent>，再 update-ref --no-deref <approved branch> <new> <expected old> CAS；不 reset/clean，不丢弃 index 或工作树。
- index、switch HEAD 的 identity/hash 由 Native 在 ResumeThread 前复验；mutable snapshot 的句柄随后释放，允许 Git 自己写入。
- commit 的 parent/tree/branch、switch 的目标 SHA/branch/clean、pull 的 ancestry/branch/clean 执行后复核。不可信结果标 GIT_POSTCONDITION_UNTRUSTED，不能继续当作成功。
- 执行过的失败、partial/unknown 结果建立 common Git directory 级 review hold。新幂等键返回 GIT_REVIEW_REQUIRED；原幂等键返回旧结果。只有本机 git-write review 的当前 job/digest 确认能解除，确认不回滚，也不证明未知远端。

## 修后实测

v13-git-external-race.test.ts：Windows、第二 OS 进程、显式 Native suspended 屏障；4 tests 含 6 个实际本地竞态场景。

| 场景 | 实际结果 | 数据与继续执行 |
| --- | --- | --- |
| add index，两种窗口 | GIT_STATE_CHANGED，拒绝启动 | HEAD 保持旧值；外部 index 保留 |
| commit index | GIT_STATE_CHANGED，拒绝启动 | 未产生额外提交 |
| commit refs | Git update-ref CAS 返回非零 | HEAD 保持外部 SHA，external-ref-data.txt 在外部 tree 可达；可能留无引用候选对象 |
| switch HEAD | GIT_STATE_CHANGED，拒绝启动 | 外部分支和文件内容保留 |
| switch dirty worktree | Git 自身 NONZERO_EXIT | 外部未提交 marker 保留，原 HEAD 保留 |

各场景强断言 failed/error、外部进程成功、实际 HEAD/数据、旧 key 不重跑、fresh key 被 hold 阻断；真实 CLI review --approve 后 hold 已解除。证据 result.json 保留在 .tooling/test-tmp/v13-f03-evidence-*。

v13-native-https-isolated.test.ts 另以独立 bare repo、loopback CGI 与临时 QuickTunnel 验证 Native HTTPS push/ff-only pull、401、远端已写入后断流及 pull 时第二进程 dirty worktree。pull 拒绝覆盖外部 marker，HEAD 保持旧值，unknown/partial 被保守记录且 fresh key 被阻断。

扩展 HTTPS 验证 9/9 通过：pull 的第二 Git 进程还实际成功改变 index、HEAD、refs。index 变化以 GIT_STATE_CHANGED 拒绝；HEAD 变化触发 interrupted/HELPER_CLEANUP_UNCONFIRMED，保留外部分支及基础文件内容，不声明清理已确认、不自动回放；refs 被外部推进后 Git 可报告完成，但 C2C postcondition 返回 GIT_POSTCONDITION_UNTRUSTED，保留外部 SHA 与工作树，不继续以成功身份运行。各 case 新 key 均被 GIT_REVIEW_REQUIRED 阻断，原数据保留。该验证体现检测/保守停止，不等于完全阻止外部 refs 写入。

## 限制

最终 snapshot 检查至 Resume 和 Git 自身执行间仍有外部修改窗口；不保证彻底排斥外部进程。固定 commit tree/parent 和 ref CAS 是独立保护，switch/pull 的 Git 拒绝与 postcondition 不是完整跨进程事务，也不保证所有瞬间观察都可归因。已有实际失败不会自动继续。测试中未观察到用户文件丢失，不能外推为任意外部恶意操作均无数据风险。
