# C2C Local V1.3 Git Write

Git Write 是面向本机仓库的结构化操作接口。它只接受固定的 Git 子命令和参数，不提供任意 shell 或任意 Git 参数入口。功能默认没有仓库授权；MCP 请求不能创建、修改或批准本机仓库策略。

## 本机授权

操作员在本机准备 JSON policy 文件，使用 `c2c git-write approve -w <workspace> --repository <workspace-relative-path> --policy <local-file>` 查看预览。预览显示仓库路径与身份、Git 可执行组件、允许的操作、分支、远端、作者、可选 GCM 与代理，并返回 digest。检查内容后，只有本机显式重跑 `--approve --digest <preview-digest>` 才会写入授权状态。审批前若仓库、Git 配置、作者或策略改变，digest 校验失败。`git-write revoke` 可撤销当前仓库授权。

policy 示例：

```json
{
  "allowedOperations": ["fetch", "pull_ff_only", "branch_list"],
  "allowedBranches": ["main", "dev"],
  "allowedRemotes": [
    { "name": "origin", "url": "https://github.com/example/project.git" }
  ],
  "approvedProxy": "http://127.0.0.1:7897"
}
```

代理是可选的，只有本机 policy 能批准。只接受 `http://127.0.0.1:<port>` 或 `http://[::1]:<port>`，端口为 1–65535；不能带凭据、路径、查询或片段。代理只加到 push、fetch、pull 的计划参数中。仓库自己的 `http.proxy`、非 loopback 代理和进程继承的 HTTP(S) proxy 环境变量都不会被信任。

## 操作范围

| 操作 | 限制 |
| --- | --- |
| `add` | 只暂存显式选择且位于仓库内的普通文件；拒绝敏感路径、reparse 路径及越界路径。 |
| `commit` | 只提交已暂存内容；拒绝敏感路径、unmerged index 与 merge/cherry-pick/revert/rebase/sequencer 进行状态；作者取自并绑定于本机预览。关闭 hooks、签名与任意 filters。 |
| `branch_list` | 只列出本机批准的分支。它是唯一允许在 unmerged index 下继续的操作。 |
| `branch_create` | 新分支名必须在批准列表中；起点限于 `HEAD`、已批准本地分支或完整 commit id。 |
| `switch` | 目标必须是批准的本地分支；计划时必须没有已修改、已暂存或未跟踪内容，并关闭子模块递归。 |
| `fetch`、`push` | 远端名、精确 HTTPS URL、分支与操作都必须分别获批；关闭 tags、prune、hooks 和子模块递归。push 将计划时绑定的完整 `HEAD` commit id 推送到获批分支，并关闭 push 签名。 |
| `pull_ff_only` | 远端和当前分支必须获批；计划时工作树必须干净；只允许 fast-forward，关闭 rebase、autostash、tags、prune、签名验证、hooks 和子模块递归。Git 会把远端获批分支 fast-forward 到当前检出的本地分支。 |

除 `branch_list` 外，计划器都会拒绝 unmerged index。`switch` 与 `pull_ff_only` 还会拒绝任何 staged、unstaged 或 untracked 变化。每个计划绑定预期 HEAD、分支、状态与 refs 摘要；排队后状态变化会导致确认失败，而不会静默套用到新状态。除 `switch` 外，执行计划会把当前 worktree 的 `HEAD` 文件作为材料锁定：普通提交与 fast-forward 更新分支引用，不需要替换该文件。`switch` 必须替换 HEAD，因此会把 HEAD 身份与摘要放进计划快照，并在执行前重算，但不在 Native 执行期间锁定。C2C repository write lock 与执行前重算、执行后状态确认用于约束 C2C 自身并发，不能保证阻止所有外部 Git 进程改变分支或 refs。

网络操作只允许 policy 中唯一的 HTTPS remote URL。Git URL rewrite、credential helper、SSH/VCS helper、自定义 protocol、HTTP redirect、cookie、额外 header、自定义 CA/TLS 证书和关闭 TLS 验证的配置都会被拒绝。`core.alternateRefsCommand`、partial-clone/promisor 配置、worktree 与 common Git 目录中的 `objects/info/alternates`，以及 `objects/pack/*.promisor` 标记也会导致拒绝。代理只能按上面的本机显式 policy 设置；TLS 证书验证始终开启。可选 credential helper 只能是该 Git for Windows 安装中的已核验 Git Credential Manager，可交互提示关闭，且 helper 文件参与材料校验与执行期锁定。

## 执行期材料与 Git bundle

Native 执行前会重新核验材料的文件身份和 SHA-256，并在进程期间锁定普通材料，阻止其被替换或写入。仓库配置、适用的 attributes、选中的 `add` 源文件、Git wrapper、Git for Windows core `git.exe`、HTTPS remote helper、Git shell，以及获批的 GCM 都是锁定材料。Git 通过 `--exec-path` 报告的 helper 目录必须与已发现的 Git bundle 匹配。

`.git/index` 单独放入 `snapshotMaterials`：它参与计划摘要与状态确认，但不作为保持打开的锁定材料，因为 Git 在 add/commit 时必须自行更新 index。Git 写入完成后依靠 Native 生命周期和 post-state 检查确认结果。索引并发写入由 repository write lock 和状态摘要检查共同约束。

持久化 Git 活动计划每 workspace 最多 256 个，每文件最多 1 MiB；计划创建使用独立原子锁。已确认安全终态的计划与完整任务记录归档，旧 ID 和幂等键可查询，但归档计划不能重新执行。活动、interrupted、partial success、未知远端与未确认结果不自动轮转；全部为这些记录时仍失败关闭。档案总磁盘占用随历史增长，未知文件/目录不清理。未知现存创建锁返回 `GIT_PLAN_STORE_BUSY`，不按时间自动抢占。

## 外部 Git 并发与失败复核

commit 从 protected state 下的私有 index 副本计算批准 tree，绑定 parent 与 branch，再使用固定内部入口 `commit-tree` 与 `update-ref <new> <expected-old>` CAS。它不从执行时 index 重新选择提交内容，不 reset 工作树。ref 冲突时不会更新批准分支；可能留下未引用候选对象。

index 与 switch HEAD 快照由 Native 在 ResumeThread 前重验。Git 必须自行写入这些文件，所以检查后释放句柄；检查至 Resume 与后续 Git 操作仍存在外部修改窗口。外部 Git 不受 C2C 锁约束。switch/pull 依靠 Git 拒绝覆盖冲突修改及执行后分支/tree/ancestry/clean 校验；不承诺彻底隔绝外部进程或回滚所有写入。

执行过的失败、partial/unknown 结果和不可信 postcondition 产生 common Git directory 级复核 hold，后续新写请求返回 `GIT_REVIEW_REQUIRED`，旧幂等键只读原结果。操作员使用 `c2c git-write review -w <workspace> -r <repository> --json` 检查本地状态及原任务，并人工核对远端；再按当前预览的 `--job <id> --digest <sha> --approve` 确认。确认不回滚文件，也不把未知远端结果改成成功。

仓库策略适用于所有持有 `git.write` scope 的 OAuth clients，本机预览明确展示此范围（F-06）。尚未实现 clientId allowlist；需要客户端隔离的 Beta 使用场景须先另行修复。

Git for Windows 的动态 DLL、操作系统组件以及 GCM 的外部运行时并没有逐个复制到计划材料中；它们仍属于宿主机 Git bundle 与 Windows 安装的信任范围。锁定 wrapper、core、remote helper、shell 和 GCM 可执行文件，不等于校验或锁定 bundle 中的全部 DLL。应使用可信、受宿主机保护的 Git 安装，并把整个 bundle 视为本机执行信任边界；本模块不自行判定安装目录 ACL。
