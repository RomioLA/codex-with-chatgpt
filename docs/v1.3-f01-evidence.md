# V1.3 F-01 脚本入口绑定证据

基线：948a0dc068e87eff0e06f1ff1d31635570bca0c3。独立审查已确认 P1；本轮补齐原材料绑定链，不重写执行体系。

## 实现

script-entry-binding.ts 识别字面的 PowerShell 外部脚本、CMD call/直接脚本、Python/Node argv 脚本，以及 program 已存在普通文件参数。自动发现与显式 materials 合并，按 canonical 路径去重；经过原路径、敏感材料、identity/hash、snapshot/digest、审批、消费、Supervisor 重查和 Native 锁定链。executable 在访问前拒绝 Windows UNC/device 路径，材料 lexical escape 在解析前拒绝。

未解析动态语义记录 entryBinding.kind=dynamic_code 和 uncertainties；本机 CLI 须另提供 --allow-dynamic，不同于 destructive-system 的 --allow-system。允许明确批准动态开发命令，不保证静态穷举所有依赖，也不把逐次 CLI 审批固化为未来工作会话的基础模型。

## 隔离动态验收

v13-script-replacement.test.ts 的五类实际 Native 场景：PowerShell 7、CMD、Python、Node、program 无脚本扩展文件参数。每类先批准并真实执行 A，确认 A marker；再批准 A、替换 B，以旧 digest 启动被 LEVEL3_MATERIAL_CHANGED 拒绝；无 B marker，Native start count 未增加。

解析测试覆盖 13 项，含外部路径不探测且未知外部 argv 标为动态语义；新增监督层测试验证显式 ./entry.js 与自动 entry.js 合并、UNC executable 提前拒绝。解释器可通过 C2C_TEST_PWSH/C2C_TEST_PYTHON 选择，缺失时明确报 BLOCKED，不默默跳过 Windows 动态验收。

最终执行结果与日志入口见 v1.3-security-fix-report.md。fixture 保留于 .tooling/test-tmp，未使用生产权限或仓库。

## 限制

扫描器不是完整 shell parser。脚本 import、模块/PATH 搜索、eval、子进程和运行时计算依赖不全部冻结。program 文件参数保守按输入锁定，已有输出文件可能因锁不能改写，需独立细化输出语义。cwd 与 Job Object 不是文件系统/网络 sandbox；受保护发行、Bridge 和用户批准程序仍是信任输入。
