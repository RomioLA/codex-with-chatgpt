# V1.3 F-01 脚本入口绑定证据

基线 HEAD：447a1f68f9b57e2539545fe0c8e82ac505907f72。本轮复现 PowerShell 显式本地执行入口漏绑定，并补齐原材料绑定链，不重写执行体系。

## 实现

script-entry-binding.ts 识别字面的 PowerShell 命令入口（`.ps1`、`.cmd`、`.bat`、`.exe`、`.com`）、CMD call/直接脚本、Python/Node argv 脚本，以及 program 已存在普通文件参数。显式 PowerShell 本地路径若缺少目标文件会标为 unresolved，并由 Level 3 在创建请求前拒绝；存在但扩展名不受支持的路径也会冻结材料并标为 `dynamic_code`，不猜测 PowerShell 的执行语义。自动发现与显式 materials 合并，按 canonical 路径去重；经过原路径、敏感材料、identity/hash、snapshot/digest、审批、消费、Supervisor 重查和 Native 锁定链。executable 在访问前拒绝 Windows UNC/device 路径，材料 lexical escape 在解析前拒绝。

未解析动态语义记录 entryBinding.kind=dynamic_code 和 uncertainties；本机 CLI 须另提供 --allow-dynamic，不同于 destructive-system 的 --allow-system。允许明确批准动态开发命令，不保证静态穷举所有依赖，也不把逐次 CLI 审批固化为未来工作会话的基础模型。

## 隔离动态验收

## 第三轮：CMD 显式可执行文件入口

`addShellEntries` 现在识别 CMD 直接命令、`call` 和 `start` 的显式 `.exe/.com` 目标；仓库内存在的目标并入材料快照，CMD `.cmd/.bat` 入口继续支持。`start` 处理已知开关、值选项和首个引号窗口标题，不把非解释器的子进程参数当成入口。PowerShell 的 `&`、直接命令、点调用和 `Start-Process` 保留在同一入口矩阵；直接调用 Python/Node 等已识别解释器时继续扫描脚本参数。

未验证、缺失或仓库外的显式执行目标产生 `unverified-execution-target`，`createLevel3Request` 在创建审批记录前以 `LEVEL3_MATERIAL_CHANGED` 拒绝。路径变量、通配符、裸命令搜索和无法解析语法保持动态/不确定标记；不放宽 `allowDynamic`。外部路径不会被探测或纳入材料。旧审批测试模拟旧版空 `materials`/空快照，当前绑定器发现新目标后拒绝审批。

## 限制

扫描器不是完整 CMD/PowerShell parser。CMD 的变量展开、转义/插入符、批处理控制流、复杂引号、环境/PATH 搜索及嵌套命令，和 PowerShell 的表达式、别名/函数、参数缩写、数组/脚本块及运行时计算，不能静态穷举；未知形式通过动态风险标记或拒绝路径处理。脚本 import、模块/PATH 搜索、eval、子进程和运行时计算依赖不全部冻结。program 文件参数保守按输入锁定，已有输出文件可能因锁不能改写，需独立细化输出语义。cwd 与 Job Object 不是文件系统/网络 sandbox；受保护发行、Bridge 和用户批准程序仍是信任输入。
