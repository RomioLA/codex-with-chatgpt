# C2C Local V1.3 Level 3 执行审批

> 历史实现说明：本文记录 V1.3 当时的 Level 3 单次审批模型，不再是 V1.3.2 Full Access 的最终产品授权合同。
> 2026-10-17 起，Full Access / Remote Parity 以根目录 `AGENTS.md`、`docs/local-permission-model-requirements.zh-CN.md` 与 `docs/remote-parity-acceptance.md` 为准。
> 本文中的逐命令 request/digest/approve 流程可继续作为 restricted mode、兼容性或历史实现，但不得被用来要求 Full Access 普通命令逐条审批。

V1.3 当前提供本机显式开启的单次命令授权，独立于 Level 1/2 的包脚本信任表。默认关闭；Level 1/2 的授权不会提升、继承或转换为 Level 3 授权。单次 CLI 审批是当前产品入口，不是未来执行体系的永久授权模型；工作会话、网页版扩权与 ConPTY 尚未实现。

启动许可绑定一次执行的材料与撤销边界，不代表必须由人逐命令点击生成；未来经独立设计的会话授权可以派生执行许可，本轮没有实现或开放这种授权入口。

## 请求与授权

远程请求通过 `createLevel3Request(workspace, clientId, spec)` 进入 `pending`。请求必须绑定 workspace、选定的 Git repository、OAuth clientId、超时、精确可执行文件、工作目录、参数或完整 shell command，以及明确列出的材料文件。创建请求不会启动进程，也不会创建执行权限。远程回执只含 requestId、digest 和过期时间；安全预览可以显示已检查过的命令内容，但不返回状态目录、材料哈希或文件 identity。

本机 CLI 使用 `setLevel3Enabled(workspaceId, true, true)` 开启功能，再通过 `listLevel3Requests` 和 `getLevel3Request` 检查完整请求。请求 10 分钟后过期。CLI 审批时必须提供本机选择的 `risk`：

- `development` 用于本机认为属于开发任务的命令。
- `destructive-system` 必须同时明确提供 `allowSystem: true`，对应 CLI 的 `--allow-system`。

风险分类只接受本机审批参数，不能由远程请求自行声明。Level 3 不会提升权限，也不声称把命令限制在 workspace 内；审批人应检查完整命令和作用范围。命令中检测到已知凭据形式、敏感键赋值或私钥内容时会拒绝创建请求，避免把凭据保存进审批状态。

## 执行边界

可执行文件必须是绝对 `.exe` 路径。`powershell` 只接受 `pwsh.exe`，由 native runner 固定附加 `-NoProfile -NonInteractive -Command`；`cmd` 只接受 `cmd.exe`，由 native runner 固定附加 `/D /S /C`。两种 shell 的 `command` 原文完整绑定在审批摘要中，shell `args` 必须为空。`program` 使用直接启动，逐项保留 `args`，不经过 shell。

工作目录与所选 repository 必须位于 workspace 内；显式材料必须是 repository 内非敏感普通文件。申请、审批和排队启动前分别计算并核对 executable、cwd 和材料的 file identity/hash。Level 3 将批准快照写入 protected state 下的 manifest；native runner 在执行期间锁定 manifest 和材料，并再次检查身份与哈希。Job Object、helper/launcher 完整性及子进程树清理仍由既有 native 执行边界负责。

`consumeLevel3Request` 把 `approved` 请求一次性改为 `consumed`，并在创建 queued job 时返回 repository、request 元数据和 GenericCommand。真正启动前，supervisor 必须调用 `resolveConsumedLevel3Request` 再次核对授权材料；该操作单次改为 `launching`。重复消费、重复 launch resolve、clientId 不匹配、digest 不匹配、过期或材料变化都失败关闭。服务重启后的 interrupted job 不得重跑。

## 本机管理

`revokeLevel3Request(workspaceId, requestId, true)` 撤销单个未结束请求。`setLevel3Enabled(workspaceId, false, true)` 撤销所有尚未结束的请求。撤销首先原子移走绑定 manifest hash 的启动许可，Native 在 ResumeThread 前核对并以禁止写入/删除共享的句柄持有许可。已成功撤销的许可不能再启动新执行；若 Native 已持许可，CLI 返回 `LEVEL3_REVOKE_BUSY`，必须重试，不能解释为成功。disable 批量事务可能先使部分许可失效再报告 BUSY，同样不得视为全部成功。running 的停止仍由 Supervisor poll 发起原 Job Object 取消；撤销授权成功不代表运行中的进程已清空，须另查询任务结束与清理结果。

审批状态、命令和 manifest 存放在 `getStateDir()/execution/level3/<workspaceId>`，该目录通过现有 protected-state 检查。状态事务使用单 workspace 锁；若检测到现存锁一律返回 `LEVEL3_STORE_BUSY`，不会自动清理或抢占锁。只有本机操作员确认没有活动 owner 后，才可手动检查并恢复遗留锁。

## 外部入口与历史容量

可识别的 PowerShell/CMD 外部脚本、Python/Node argv 脚本及 program 普通文件参数自动进入材料摘要。显式与发现的同一 canonical 文件去重，越界、UNC/device executable 和 reparse 材料拒绝。静态扫描不是完整解释器：无法确定的动态入口展示 `entryBinding.kind=dynamic_code` 与 uncertainties，审批另需 `--allow-dynamic`，不等同 `--allow-system`。脚本内部 import、动态依赖、PATH/模块解析和系统 DLL 不保证冻结。program 已存在文件参数按输入保守锁定；既有输出文件也可能被锁，输出语义需在后续独立授权设计中细化。

256 条是活动审批记录上限。未消费的安全终态与已确认进程清理的终态可归档，原 request ID 仍能查询；consumed、launching 和不确认结果保留，不能自动删除换取容量。归档保留审计与幂等，磁盘历史会增长，尚无自动清理保留期。

Native 验证执行材料、manifest 和启动许可，不独立解析完整 workspace/client/risk/approval 语义。受保护 Bridge 与发行材料是授权信任边界（F-04）；许可修复不能被宣称为 Native 完整授权裁决。
