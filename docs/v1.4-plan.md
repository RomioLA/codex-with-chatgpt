## 版本边界

V1.3.2 已完成 Full Access → Remote parity。V1.4 增加批量证据工具与持久确定性任务，使 C2C 更适合 AI 驱动的非 GUI 软件工程工作。任何 V1.4 API 都沿用既有本机权限和 OAuth 能力，不引入 Level 3、trusted-command prerequisite、逐命令人工确认或新的权限级别。

V1.4 Task 是不可变、有限、确定性计划的本地执行器。它没有模型调用能力、语义规划循环、自动扩展范围或自行生成新步骤。运行中的 Task 如需模型判断，进入 WAITING_FOR_MODEL 并停止 dispatch。

## Existing Architecture

调查均基于指定 commit 的新 V1.4 worktree。

- **MCP 层：** src/mcp/server.ts 集中注册 workspace 与 execution 工具；src/mcp/http.ts 维护工具追踪名称。OAuth scope 由 handler 显式检查。
- **读取与搜索：** Workspace.readFile() 在 src/workspace/manager.ts 完成 workspace 路径 canonicalization、敏感路径拒绝、二进制检测、行分页与完整文件 SHA-256。单文件最大返回 1 MiB；默认按行返回。首行大于 maxBytes 时现有实现仍可能超出预算，批量 API 不能依赖该边界行为。searchWorkspace() 在 src/workspace/search.ts 一次处理一个查询，最多返回 200 条，单条 snippet 最多 500 字符；ripgrep 与 Node fallback 跳过大于 2 MiB 的文件，但没有全局扫描文件数、字节数或总耗时上限，也没有稳定排序合同。
- **Execution Job：** ExecutionSupervisor 一次创建一个命令 job，负责排队、幂等、超时、权限复核、取消和 native helper 生命周期。Full Access 路径是 startFullAccess()，不经过 Level 3 或 trusted-command registry。
- **Job Store / 输出：** ExecutionJobStore 存于 state dir 的 workspace 专属目录，版本化 JSON 通过同目录临时文件与 atomic replace 写入；每 workspace 最多保留 50 个活动索引 job，归档终态记录。stdout/stderr 使用每流最多 4 MiB 的分段 writer，每段 256 KiB；MCP 输出分页最多 64 KiB，按 UTF-8 边界读取。
- **授权：** Full Access job 记录 workspaceId、OAuth clientId、Windows session 身份指纹、grantId 与 request hash。Supervisor 在排队启动前复核，Native helper 在 ResumeThread 前持有 launch permit 再次核对，Supervisor 每 250 ms 检查撤权。grantId 防止撤权后重新授权使旧 job 复活。
- **进程与重启：** Windows helper 将子进程放入 Job Object；owner 丢失会触发进程树清理。Job Store 启动时把 queued/running/cancelling job 转为 interrupted / BRIDGE_RESTARTED，不重新排队，也不恢复旧 runner。发生 side effect 后、结果持久化前的 crash 不能证明操作是否完成。
- **锁与写入：** src/execution/repository-write-lock.ts 按 common Git directory 身份提供跨 worktree 的协作锁；未知锁不会自动抢占。该锁目前服务于 repository-scoped job，不是通用 Full Access shell 的 OS sandbox。结构化写工具另有 expected hash、文件身份检查和原子替换。
- **会话 checkpoint：** src/session/state.ts 中的 TaskCheckpoint 是轻量对话协议状态，不含可执行步骤、子 job 或持久 Task 状态，不能当作 Task Store。

## External Technical Research / Design Alignment

本节记录外部研究吸收的设计原则，不复制外部项目代码，也不引入其依赖。

- **MCP Tasks Extension（2026-07-28）**：durable task methods 为 tasks/get、tasks/update、tasks/cancel，标准状态 working、input_required、completed、failed、cancelled；标准没有 tasks/list，task ID 应按 capability-style reference 保护，且每次查询重新授权。C2C 内部 PersistentTask 不绑定 MCP SDK 1.30 experimental task wire format。
- **MCP filesystem multiple-file precedent**：作为批量读取 API 设计参考；C2C 仍保留自己的 workspace scopes、敏感路径、结果 caps 和 per-item error contract。
- **ripgrep structured JSON**：继续使用 rg --json 并行扫描；关闭用户配置影响，以 C2C wrapper 统计预算并在收集后排序。
- **Temporal-style durable workflow principles**：deterministic orchestration、持久 dispatch history、reconcile 外部活动、未知 side effect 不 replay。仅参考原则。
- **BullMQ / Celery**：仅概念比较；不引入 broker、Redis、后台 daemon 或外部 job framework。
- **GitHub Actions Runner lifecycle**：graceful cancel 后仍须有 process-tree forced termination；继续复用 C2C Native Helper 与 Windows Job Object。
- **Node SQLite**：调查机器的 Node 24 内置 SQLite 不改变 package engines Node >=20；V1.4 继续 bounded JSON + atomic replace + strict schema + corruption fail-closed。
- **MCP SDK baseline**：当前 pnpm lock 解析为 @modelcontextprotocol/sdk 1.30.0，package.json 仍声明 latest。V1.4 A+B 只按 lock-resolved 1.30.0 规划；SDK v2/modern Tasks wire compatibility 与显式 pin 决策另立任务，不改依赖。

## SUBAGENT-A — Batch Architecture

只读调查结论：

- Batch MCP 注册放在 src/mcp/server.ts 的现有 workspace 工具区，另设 batch/evidence 注册模块；domain 层复用 Workspace.resolve()、Workspace.readFile() 和 searchWorkspace()，不递归调用 MCP handler。
- read_file 与 search_workspace 已有 scopes 分别为 workspace.read、workspace.search。批量 API 继续使用它们；不增加 OAuth scope。外部路径读取使用独立 scope 和 host-path boundary，不混入 workspace batch。
- 不能无界 Promise.all 或只拼接无限次单项调用：单项读取会扫描完整文件计算 hash；单项搜索会遍历目录且没有总扫描预算；单项返回上限不等于批次响应上限；搜索与后续读取间文件可能变化。
- 批量读取必须显式执行单文件、总字节与条目 caps，并修正超长单行溢出；批量搜索需固定排序、共享总扫描预算、部分失败逐项返回。Evidence snippet 必须来自读取时的文本与 hash，不能把搜索旧内容和读取新内容拼作一个证据项。
- 新工具名也要加入 src/mcp/http.ts 的追踪白名单。无需新的 HTTP route。

## SUBAGENT-B — Persistent Task Architecture

只读调查结论：

- 当前 ExecutionJob 是单条命令记录，没有 Task、step、checkpoint、retry lineage 或 Task→Job 关系。ExecutionJobStore 的版本校验、atomic replace、幂等索引、分段输出和 ExecutionSupervisor 生命周期适合作为 child 执行底座；ExecutionJob 仍保持一个 job 对应一个命令。
- 新增独立 Task aggregate / TaskStore / Task state machine；Task 可有 0..N 个 child ExecutionJob，按固定顺序最多同时运行一个 child。每个命令 step 保存稳定 child idempotency key 与 jobId。
- TaskStore 与 JobStore 是两个独立原子存储，没有跨 store 事务。创建 Task step 与启动 child 之间用持久 checkpoint、稳定幂等键和重启 reconciliation 处理；不承诺 side effect exactly-once。
- Bridge crash 时旧 ExecutionJob 会被标成 interrupted。运行中命令的结果不确定时，Task 进入 WAITING_FOR_MODEL 并附原因，不重复启动命令。已确认 checkpoint 后的下一步可在重新授权后继续。
- Execution Job 的 segmented output 保留给命令输出；Task 保存摘要、step 状态、证据引用和有界非命令结果，task_result 分页，task_output 委托给现有 job output API。

## SUBAGENT-C — Permission / Security

只读调查结论：

- Batch/Task 请求体不得自报 workspace、client、用户、权限模式或 grant。服务端绑定当前 Bridge workspace、已验证 OAuth clientId/scopes，以及当前 session 身份指纹和 grantId。
- 当前没有稳定的 OAuth 人类 userId；本机 Windows session 指纹（仅保存 hash）与 OAuth clientId 一起作为执行主体绑定。不得存原始 SID、session LUID 或 token。
- 含 Full Access execution step 的 Task 创建时必须有当前 level2 session grant；每次 dispatch 前、Native launch permit 处与运行期复用 ExecutionSupervisor 检查。撤权停止后续 step、取消 queued child、终止 running child；权限重新授予会生成新 grantId，旧 Task 不复活。
- 读取、搜索、Task status/result/output/cancel 分别复用既有 workspace 与 execution scopes；不新增权限级别或逐命令审批。OAuth token 过期/轮换与本机 Full Access 撤权是不同事件；token 不存入 Task，API 请求仍需当前有效 token。
- repository-write-lock 只提供 C2C repository-scoped 写操作间的协作互斥，不构成 Full Access cwd 的安全边界。Task 的 repository scope 若存在，需绑定 canonical RepositoryIdentity 并复用该锁；任意 Full Access 命令不得被描述为 OS sandbox。
- 命令输出复用现有 StreamingSanitizer 和 segmented writer。Evidence 源文本还必须经过 sensitive-path 规则和已知 secret/private-key sanitizer；启发式 sanitizer 不能证明任意秘密都已发现。

## Final Architecture Decisions

1. **batch_read：** 单独的 MCP tool。它有独立的多文件 envelope、聚合字节预算、逐项错误和分页，不扩大 read_file 的单文件语义。
2. **batch_search：** 独立 MCP tool；domain 层复用/扩展 workspace search primitive。输入一次提交多 query 和 path scope，使用 ripgrep 的 --json --no-config 保持并行搜索，不使用 --sort path；收集有界 structured JSON 后由 C2C 按 normalized workspace-relative path、line number、稳定 match tie-break 排序。旧 search_workspace schema 保持兼容。
3. **collect_evidence 最小 schema：** 版本化 EvidenceSnapshot domain object，经当前 C2C collect_evidence adapter 返回分页 representation；含 schemaVersion、snapshotId/packageId、workspaceId、owner client binding、capturedAt、requestHash、packageHash、Git repository identity/HEAD/status、显式请求文件的 size/mtime/SHA-256/ranges/snippets、显式 searches 与 matches、显式 execution job/output metadata refs、omitted[]、逐项 errors[]、truncated、nextCursor。来源路径仅为 workspace-relative；每项带 source hash 和 redaction/truncation 状态。无自主 discover、无命令执行。
4. **Evidence Package 是否落盘：** standalone collect_evidence 不写 repo 或持久文件；由 EvidenceSnapshot 内存 store 支持分页，snapshotId/cursor opaque 且绑定 owner client、workspace、request hash 与 source hashes。上限 4 个/workspace、每个最多 2 MiB、TTL 10 分钟；Bridge restart/过期后返回 CURSOR_EXPIRED。当前 C2C adapter 只暴露分页 tool response；未来可另加 MCP Resource adapter，不在 V1.4 实现。作为 Task step 时，只将 bounded、sanitized、canonicalized 结果写入 TaskStore，最多 1 MiB，禁止无限保存原始文件内容。
5. **Batch 同步或 Persistent Task：** batch_read/search/collect_evidence 都是单次同步、有硬 deadline/scan/output caps 的工具。达到 cap 返回 truncated/continuation 或逐项 error；不自动创建 Task。需要执行命令、多步骤顺序、超过 batch deadline 的计划时，GPT 显式调用 task_create。
6. **Task 与 Execution Job：** Task 是计划、checkpoint 和结果聚合；ExecutionJob 仍是每条命令的生命周期对象。Task 调用 ExecutionSupervisor.startFullAccess() 创建 child job，不另建 native process runner。
7. **一个 Task 的 jobs 数：** 允许 0..8 个 child execution jobs，按 plan 顺序运行，每 Task 同时最多一个；workspace/global 并发仍服从现有 Supervisor slots。step 与 child job 一对一，每次 retry（仅允许的安全读取 retry）是新 attempt。
8. **Task 最小 step 类型：** batch_read、batch_search、collect_evidence、只读 git_status/git_diff、execution（完整且已校验的 Full Access program/PowerShell/CMD 请求）、有限的确定性 assertion。不得有“让模型决定下一步”、自动生成命令、无限 wait、动态范围扩展或隐式重试 step。
9. **V1.4 首版允许的 steps：** 上述只读步骤、bounded assertion 和最多 8 个明确 execution steps。每 Task 最多 16 steps、计划 JSON 最多 256 KiB、单 child timeout 沿用 1..3600 秒、Task 总 wall-clock cap 4 小时。Execution step 使用 Full Access generic execution，绝不要求 Level 3 或 trusted registry。
10. **Task Store：** getStateDir()/persistent-tasks/<workspaceId>/tasks.json，workspace 隔离；沿用同目录临时文件 + atomicReplace、严格记录校验、私有权限、corruption fail closed。execution step 含 PREPARED/CHILD_BOUND/OBSERVED/CHECKPOINTED dispatch journal，保存 attempt、derived child key、childJobId、observed outcome 与 checkpoint。每 workspace 最多保留 50 个活动索引任务；只归档明确可归档的终态记录，WAITING_FOR_MODEL、INTERRUPTED/结果不确定记录不自动丢弃。
   - **Major Wave 3 实施差异：** 本轮以 32 个持久 Task/Workspace、64 MiB envelope、每 Task 累计 checkpoint 结果 1 MiB 为硬上限；不驱逐或归档，达到上限时拒绝新增/更新。Full Access child job 另持久化由 ExecutionSupervisor 解析得到的可选 canonical repositoryScope，以复用现有 repository lock；权限语义不变。后续归档策略仍待独立评审。
11. **Task schema version：** envelope version: 1，字段含 workspaceId 和 tasks[]；Task 含不可变 planVersion: 1、规范化 plan/hash、owner clientId/workspaceAuthorizationEpoch、session fingerprint/grantId、permission/scopes、state、stepIndex/completedSteps、step checkpoints、per-step dispatch journal、child job IDs/idempotency hashes、有界结果 refs、timestamps、lastCheckpoint、failure/blocked reason。未知 schema/损坏记录不迁移、不执行，保留原件并将 store 标为 corrupt。
12. **Restart 可恢复状态：** QUEUED 且未启动的 Task 在完整 auth recheck 后可排队；最后 checkpoint 完整且当前无未决 child 的 RUNNING Task 可从下一 step 继续。PREPARED 且健康 JobStore 按 stable key 查无 child 时才首次 dispatch；找到 child 则绑定旧 job，不创建第二个命令。child terminal outcome known 时写 OBSERVED 后 CHECKPOINTED；已观察 terminal 但 Task checkpoint 缺失时重读同一 child 补 checkpoint。只读 batch step 未提交结果可按固定输入重收集并记录新 hash；source hash 不符时 WAITING_FOR_MODEL。child interrupted/unknown 或可能已有 side effect 时进入 WAITING_FOR_MODEL，绝不自动 replay command。
13. **Bridge crash 中进程：** 复用 Native helper/Job Object owner-lost 清理。重启后 JobStore 将活动 child 记为 interrupted；Task 对账后进入 WAITING_FOR_MODEL，failureReason 为 EXECUTION_OUTCOME_UNKNOWN，保留 child job 与最后 checkpoint，不 attach、不假定成功、不 replay。Helper 树清理不构成 side effect 回滚证明。
14. **Retry：** execution command 自动 retry 默认 0。仅在健康 JobStore 的 stable-key lookup 证明 child 从未创建/启动时，可用相同 attempt 与 key 继续首次 dispatch；这不是新 retry。batch_read/search/git read 等纯读取 step 可按 plan 对 transient error 最多 retry 一次。permission denied、source changed、store corruption、确定性非零退出及 SIDE_EFFECT_MAY_HAVE_OCCURRED 不自动 retry；需复跑副作用命令时，经模型复核后创建新 Task。
15. **Idempotency：** task_create 要求 16..128 字符 key；按 OAuth client + key hash 查重。同 key/同规范化 plan 返回原 Task，同 key/不同 plan 返回 IDEMPOTENCY_CONFLICT。child key 由 canonical deterministic derivation 从有序 tuple ["c2c-task-child-v1", taskId, stepId, attempt] 产生：前缀 c2c-task-v1- 加 hex(SHA-256(UTF-8(canonical_json(tuple))))。Bridge restart 后不得随机重建。key 只用于 deduplicate dispatch、reconnect child 和 crash reconciliation，不承诺任意外部副作用 exactly-once。
16. **Cancel：** API 请求可重复调用且返回同一已持久状态；queued 任务直接取消。running 先原子写入 CANCELLING、停止后续 dispatch，再向当前 child 发一次 cancel；只有 Job Object 进程树清空获确认才报 CANCELLED。结果未确认时为 INTERRUPTED/CANCEL_UNCONFIRMED。接口定义 at-most-once cancel request，不承诺撤回已完成副作用或 exactly-once。
17. **Permission revoke：** 含 execution 的 queued/running Task 绑定创建时 Full Access context；revoke 后不启动 queued child，running child 沿用 250 ms permission poll、launch permit、Job Object cancellation，Task 不再推进。重新授予权限会换 grantId，旧 Task 不恢复。纯读取 Task 不要求 Full Access grant，但仍受 workspace OAuth scopes 限制。已发生的外部副作用不能回滚。
18. **grant ABA：** 绑定 workspaceId + oauthClientId + workspaceAuthorizationEpoch + sessionIdentityFingerprint + grantId + permissionMode + required scopes；每个 execution child 也保存现有 sessionGrantFingerprint + grantId。不得只比较 level2 字符串或 session fingerprint。
19. **Repository lock：** Task 可声明 workspace 内 canonical repository_path，创建及每个 execution dispatch 都复核 RepositoryIdentity；执行期间用现有 commonGitDirectory lock，并把 child jobId 作为 lock owner。任务 step 之间不长期占锁；C2C 的 repo-scoped 写 job 与同锁互斥。Full Access 命令仍可能触及 scope 外仓库，所以这是协作锁，不是 sandbox。Bridge crash 后未知锁遵循现有 fail-closed 人工 reconciliation，不擅自抢锁。
20. **Output：** child stdout/stderr 全部来自现有 sanitizer + ExecutionJobStore segmented writer。Task 记录 child job IDs 和 output offsets；task_output 委托 Supervisor 的 readOutputForClient()。task_result 的非命令结果每 Task 最多 1 MiB、单页最多 64 KiB；超额显式 truncated/omitted，不塞满 MCP response。
21. **Task API：** 通过 proprietary C2C Task API Adapter 提供 task_create/status/list/result/output/cancel。task_status 返回 state/currentStep/completedSteps/fixed totalSteps/timestamps/lastCheckpoint/blockedReason，不返回百分比。task_list 是 C2C proprietary recovery/discovery API，不属于标准 MCP Tasks Extension；其结果有界、按 owner OAuth client 与 workspace 隔离，禁止跨 client 枚举。taskId 是 opaque/unguessable reference。每次 create/get/list/result/output/cancel 都重新验证 token、workspace、scope 与 owner client。未来 adapter 状态映射：QUEUED/RUNNING/CANCELLING→working，WAITING_FOR_MODEL→input_required，COMPLETED→completed，FAILED/INTERRUPTED→failed，CANCELLED→cancelled。
22. **禁止 Autonomous Agent：** plan 创建后只读不变；Task runtime 不调用模型、不判断语义、不添加命令、不放宽权限。任一步需新判断时 WAITING_FOR_MODEL；恢复模型判断应由 GPT 新建后续 Task。
23. **A+B 实施顺序：** Wave 1 先冻结 SDK baseline、共享限额、canonical hash、cursor、search scan budget、--no-config 与 C2C post-sort contract；其后 batch_read/search 与 Task domain/store 可并行。collect_evidence 等 Batch API 稳定后再做；dispatch journal/TaskStore 稳定后 TaskSupervisor 仅经 ExecutionSupervisor 创建 child；最后接当前 proprietary Task API adapter 并保留未来 MCP Tasks adapter 边界。
24. **可并行开发：** Wave 1 contract 冻结后，batch_read 与 batch_search 的 domain/tests 可并行；Task types/store/state machine 可与它们并行，因为文件隔离。collect_evidence 依赖 Batch API；Task executor 依赖 A/B 合同与 job bridge；MCP 注册、runtime 注入和 release integration 必须串行合并。

## V1.4 A — Final Scope

### batch_read

**MCP input**

- items：1..16 项，每项为 id、path、可选 start_line/end_line 或 offset_bytes、expected_hash；id 唯一，路径必须为 workspace-relative。分页 continuation 使用 UTF-8 安全的 byte offset，可在超长单行内部继续。
- per_file_max_bytes：默认 32 KiB，硬上限 64 KiB。
- max_total_bytes：默认 256 KiB，硬上限 512 KiB。
- source scan：为保留完整 `sourceHash`，单文件完整扫描硬上限 64 MiB，整批累计扫描硬上限 256 MiB，共享 deadline 10 秒；底层 bounded read 在读取/hash 时执行剩余字节与 deadline 检查，并统计实际 `sourceBytesScanned`。
- cursor：绑定 workspace、owner client、规范化请求 hash 与每项 source hash/position。

**Result**

每项返回 id/path/ok/sizeBytes/contentHash/startLine/endLine/startByte/nextOffsetBytes/content/truncated/error。整体返回 results/returnedBytes/truncated/nextCursor。结果遵照请求项顺序；单项路径、权限、not found、binary、oversize 错误不丢弃其它成功项。超长单行按 UTF-8 byte offset 分页，可继续读取同一行且绝不越 cap。

**Security / limits**

复用 Workspace.resolve() 和 sensitive-path policy；workspace 外路径、symlink escape、敏感文件拒绝。检查 workspace.read，不增加权限级别。按 UTF-8 边界分页；跨页若 expected_hash 与当前完整内容 hash 不匹配，返回 SOURCE_CHANGED。

完整源扫描超出单文件或批次剩余预算时，逐项返回 `SOURCE_SCAN_LIMIT`；共享 deadline 到期返回 `DEADLINE`。这些错误不含 `sourceHash`，也不将已扫描前缀 digest 作为完整 hash 返回。legacy `read_file` 不使用这些 batch-only 限额。

**实现文件**

新增 src/workspace/batch.ts、src/mcp/batch-tools.ts；修改 src/workspace/manager.ts 提供严格 byte-bounded、UTF-8-safe read primitive；修改 src/mcp/server.ts 注册与 scope gate、src/mcp/http.ts tool name list。

**测试**

新增 workspace batch 与 MCP batch integration tests：16/17 项、per-file/total cap 边界、超长单行、UTF-8 boundary、敏感/不存在/binary partial errors、source hash 跨页变化、响应字节数上限、未授权整批拒绝且不启动子项。

### batch_search

**MCP input**

- queries：1..8 项；每项为 id、query、mode（literal 或 regex）、可选 paths/glob/max_matches。query 最多 512 字符，path scopes 最多 16 个。
- 每 query 默认返回最多 20、上限 50；整批最多返回 100 matches；snippet 最多 500 字符，整页最多 256 KiB。返回 match limit 不提前终止扫描：在 scan budget 内统计 matchesObserved，以有界 top-K collector 保留排序键最小的结果，再由 C2C post-sort；scan budget 截断时显式标记 partial completeness。
- 每批扫描最多 256 MiB、10,000 个 file entries、10 秒；match limit 与 scan budget 独立。返回 `bytesScanned`、`filesConsidered`、`filesScanned`、`matchesObserved`、`matchesReturned`、deadline/budget truncation reason；rg summary 若不能可靠提供计数，由 C2C wrapper 维护。完整完成的 rg scan 使用实际统计；被中断且无法取得完整 summary 时，`bytesScanned` 按已预留字节保守计费，表示预算记账上界，不声称是精确物理读取量。
- 完整性字段分别表示扫描与结果：`scanComplete` 仅表示请求的允许范围已完成扫描；`resultsComplete` 表示没有 match 被单 query 或整批上限丢弃；`complete` 等于两者 AND。MATCH_LIMIT、SCAN_BYTE_LIMIT、ITEM_LIMIT、DEADLINE 均不得产出 `complete: true`。MCP 分页游标只表示快照页面续读，不改变快照级完整性字段。
- 输出 query 按输入顺序，match 按规范化相对路径、行号排序；path scope 去重。

**Pagination / errors**

使用绑定 workspace/client/request hash 的内存 snapshot cursor，页面保持固定顺序。snapshot 最多 4 个/workspace、2 MiB/项、10 分钟；超限返回 CURSOR_CAPACITY，过期/重启返回 CURSOR_EXPIRED。每 query 独立错误并继续其余 query；顶层 schema/scope 错误拒绝整批。regex 只经 ripgrep 的受限实现执行；不可用时返回明确 per-query error，不回退到语义不同且无时间界限的 JavaScript regex。literal 可用现有 ripgrep/Node fallback。

**Security / implementation**

新独立 tool，复用并扩展 src/workspace/search.ts 的 ignore/sensitive/path scope；路径不得脱离 workspace。rg 保持并行并输出有界 JSON；C2C post-sort，不以 --sort path 牺牲并行。调用加 --no-config，避免用户 ripgrep 配置改变 tool semantics。literal Node fallback 执行同样的 file/byte/deadline/path/file-size/sensitive/order budgets；regex 不回退到无界 JavaScript RegExp，受控 rg 不可用时返回 ENGINE_UNAVAILABLE。query/match return limit 与 scannedBytes/filesConsidered/filesScanned/matchesObserved/deadline 分别计数；超预算显式返回 truncation reason 和 partial completeness。query/match 来源标注为不可信 workspace 内容。

新增/修改 src/workspace/search.ts、src/workspace/batch.ts、src/mcp/batch-tools.ts、src/mcp/server.ts、src/mcp/http.ts。

**测试**

验证 --no-config 隔离用户配置、rg 并行结果经 C2C post-sort 稳定、match limit 与 files/bytes/deadline budgets 分离、扫描计数与 truncation reason、literal fallback 同等限额、regex ENGINE_UNAVAILABLE、invalid pattern、path/glob、partial errors、cursor 绑定/过期/Bridge restart 和响应上限。

**PLAN_DELTA**

- **DELTA：**短于 2 个字符的 batch query 返回 `QUERY_TOO_SHORT`；search primitive 在大型目录枚举上限触发 `ITEM_LIMIT` 时可能报告 `filesConsidered: 0`，batch 仍将其作为共享预算终止原因，并停止后续 query。
- **WHY：**保留底层 bounded search 的实际错误与计数，不推造已检查文件数；继续扫描后续 query 会越过共享 batch 资源合同。
- **IMPACT：**调用方需检查 query 级 issue 与 `stopReasons`；`filesConsidered` 为 0 不代表没有触发目录枚举上限。

### collect_evidence

**MCP input**

显式 plan：files[] 最多 16 项（路径与行范围）、searches[] 最多 8 项（明确 query/path/glob）、repositories[] 最多 4 项（明确路径，读取 Git info/status/selected diff）、execution_jobs[] 最多 8 项（明确 jobId 与 stdout/stderr 元数据引用）。整体 deadline 10 秒；不允许隐含目录 discovery、不执行 command/test、不接受 external path。

**EvidenceSnapshot v1 与当前 MCP representation**

- 内部 envelope：schemaVersion/snapshotId/workspaceId/ownerClientId/capturedAt/requestHash/packageHash/sourceHashes/complete/truncated。当前 MCP adapter 返回 `snapshotId`、`page` 与可选 `nextCursor`；未来 Resource adapter 可复用同一 snapshot domain，不改变内部 schema。
- files[]：workspace-relative path、sizeBytes、mtime、contentHash、selected ranges/snippets、redacted、truncated、status。
- 长行范围若因 snippet 上限截断，`nextOffsetBytes` 指向实际返回 UTF-8 内容末尾，`continuationMode="byte"` 且 `nextStartLine` 保持当前行；调用方使用该 offset 和 `contentHash` 通过 `batch_read` 续读。因 200 行上限停止时，mode 为 `line`，offset 与 `nextStartLine` 指向首个未返回行。若 sanitizer 拒绝或截断输出，正文整体 withheld，offset 回到 range 起点，mode 为 `unavailable`，不得从该 range 续读。`collect_evidence.nextCursor` 只分页 Evidence 记录。
- searches[]：query id/hash、engine、稳定排序 matches、实际观察到的来源文件 hash、stopReasons、truncated/status。
- repositories[]：canonical repository identity hash、branch、HEAD、dirty/status hash、capturedAt。
- artifacts[]：显式 execution job ID、client ownership result、state/exit/failure metadata、output offsets/retention/truncation refs；不重新运行 job。
- omitted[]/errors[]：每个缺失、拒绝、源变更、超预算对象及固定 error code。
- provenance：明确请求 hash、确实从读取数据取得的 source hashes 与收集时间。packageHash 对 canonicalized package JSON 求 SHA-256。

**Pagination / security**

逻辑 package 在内存 snapshot 分页，不生成 repo 文件或单独落盘 artifact。文件读取期间以同一 bounded read 计算完整 contentHash 并比较前后文件身份/元数据；文件变化标 `SOURCE_CHANGED`。内容先过 sensitive-path policy，再通过已有 token/private-key sanitizer；private-key 命中则省略正文并标 restricted。standalone package 最多 2 MiB；structured page payload 最多 248 KiB，为 Streamable HTTP JSON-RPC envelope 保留 8 KiB，实际 MCP response hard cap 为 256 KiB。超额显式省略并带原因。作为未来 Task step 时，计划中的 package cap 为 1 MiB，TaskStore 持久化该 bounded sanitized 结果/checkpoint；该 Task 能力不属于本轮实现。工具描述明确 workspace 内容为 untrusted data。

**PLAN_DELTA**

- **DELTA — Search snapshot：**search primitive 不提供完整候选文件清单，也不从首次扫描的字节流生成源 hash。Evidence 对结果执行两次 bounded scan 并比较 match set；即使 match set 一致，结果仍为 `partial` 并带 `SOURCE_SNAPSHOT_UNAVAILABLE`。提供的 match/path hash 是后置读取观察值，不声明为首次搜索快照 hash。若两次 match set 不一致，标 `source_changed` 并清空 matches/source hashes。
- **WHY：**不能从路径与行号推导不可变证据；当前 primitive 无法证明搜索期间整个候选集合及其内容保持原子一致。
- **IMPACT：**只有实际读取并哈希的对象才进入 `sourceHashes`；调用方可区分已验证的后置观察与不可用的搜索快照。
- **DELTA — Repository diff hash：**仓库 `sourceHashes` 不包含脱敏或分页后的 diff 正文；canonical package hash 覆盖 snapshot 中实际返回的 diff 内容。
- **WHY：**diff 是受界限、可能脱敏/截断的响应内容，不是原始仓库源文件的完整 hash。
- **IMPACT：**`sourceHashes` 只表示真正读取的源对象和 Git identity/status；`packageHash` 承诺返回 package 的完整性，不声称能复算被省略的原始 diff。
- **DELTA — MCP page wire size：**`batch_read`、`batch_search` 与 `collect_evidence` 的完整数据只放入 `structuredContent`；文本 content 给出简短计数摘要。每个结构化页最多 248 KiB，HTTP 集成测试验证包括 JSON-RPC 封装的完整 JSON response 不超过 256 KiB。
- **WHY：**MCP tool response 同时携带 `content` 与 `structuredContent`；重复放入完整 page 会使 wire response 超过页上限。
- **IMPACT：**客户端应读取 `structuredContent` 获取完整结果；人类可读的 content 用于显示返回数量和继续分页提示。

## V1.4 B — Final Scope

### Task plan / schema

新增独立 PersistentTask，计划 immutable。Envelope 严格校验 version:1/workspaceId/tasks[]。Task 保存 taskId、owner OAuth clientId 与 workspace authorization epoch、planVersion/hash、创建时 sessionIdentityFingerprint/hash、grantId、permission mode、required scopes、state、stepIndex、completedSteps、step attempt/checkpoint、child job IDs、结果/输出 references、created/started/updated/finished timestamps、lastCheckpoint、failure/blocked reason、request idempotency hash。不得存 access/refresh token、原始 SID 或环境变量秘密。

Plan 只接受已知 union step，最多 16 steps、8 execution steps、256 KiB canonical JSON、单 Task 总时限 4 小时。创建前一次性验证所有 step、workspace path、scope、timeout、cwd/executable 和输入 cap；运行中 plan 不可追加或改写。

### Dispatch Journal / stable child idempotency

每个 execution step 持久化 dispatch journal，状态严格为 PREPARED → CHILD_BOUND → OBSERVED → CHECKPOINTED：

- PREPARED：TaskStore 已原子保存不可变 step、attempt 与确定性 child idempotency key；尚无已绑定 child job ID。
- CHILD_BOUND：找到/创建的 Execution Job ID 已写回 TaskStore。
- OBSERVED：已读取 child terminal state 与可确定 outcome。
- CHECKPOINTED：TaskStore 已持久化该 step 的最终结果 checkpoint。

child key 统一派生为 c2c-task-v1- + hex(SHA-256(UTF-8(canonical_json(["c2c-task-child-v1", taskId, stepId, attempt]))))。相同 taskId/stepId/attempt 在 Bridge restart 后生成完全相同的 key；不得随机生成。Task create key 与 child key 分属不同幂等域。

恢复规则：

1. PREPARED 且 healthy JobStore 按 owner + key 查无 child：允许首次 dispatch，仍使用原 attempt/key。
2. PREPARED 或 CHILD_BOUND 查到 child：绑定已有 job；不创建第二个 command。
3. child terminal 且 outcome known：写 OBSERVED，再写 CHECKPOINTED。
4. child 已 terminal、Task checkpoint 未写：重读相同 child outcome，补齐 checkpoint，不重跑。
5. child interrupted、结果不确定或 SIDE_EFFECT_MAY_HAVE_OCCURRED：WAITING_FOR_MODEL；COMMAND MUST NOT AUTO-RETRY。

TaskStore 与 JobStore 仍无跨-store transaction。stable-key lookup 只用于 deduplicate/reconnect/reconcile；不宣称 exactly-once external side effect。

### States / transitions

QUEUED → RUNNING → COMPLETED|FAILED|WAITING_FOR_MODEL；取消或权限 revoke 时 QUEUED|RUNNING → CANCELLING → CANCELLED。Bridge crash 后若 child execution job interrupted/结果未知，Task 进入 WAITING_FOR_MODEL；只有取消/进程树清理无法确认时才进入 INTERRUPTED。WAITING_FOR_MODEL 可被取消，不会在模型之外自行改变计划。终态不复活。每次 transition 与 step checkpoint 都 atomic persist，再 dispatch 后续 step。

### Store / executor / Execution Job

新增 src/execution/task-types.ts、task-state-machine.ts、task-store.ts、task-supervisor.ts、Task archive helper。TaskStore 位于 state dir，不写 workspace。JobStore 继续专管 child ExecutionJob 和分段输出。TaskSupervisor 顺序执行最多一个 child；创建 child 前先持久化 step attempt 与派生 idempotency key，再经 ExecutionSupervisor.startFullAccess() 查重/创建；保存 child jobId 后观察原 job 状态。两 store 间不假设事务。

纯读取 step 失败仅按 plan 允许的一次 transient retry；command step 失败或 interrupted 不自动 retry。健康 JobStore stable-key lookup 证明 child 不存在时，只能继续同一次 PREPARED dispatch，不增加 attempt。Task crash recovery 通过 Task checkpoint + child job idempotency lookup 对账；store corrupt 时不启动任何 Task。

### Cancellation / recovery / permission binding

Task cancel 首先持久化 CANCELLING，再禁止下一 step dispatch；child cancel 使用 Supervisor 的 Native cancel/Job Object。仅在树清空确认后标 CANCELLED；helper/Bridge 状态未知时标 INTERRUPTED 并保存证据。不会把取消表述成撤回副作用。

Task 创建及每次 step dispatch 都核对当前 workspace、owner client、workspace authorization epoch、有效 scopes、permission mode、session fingerprint、grantId。AuthStore 的 explicit revoke-all 持久化递增 epoch，Bridge task supervisor 取消旧 epoch；token refresh/自然过期不递增。Full Access revoke 后 queued 不启动、running child 停止，重新授权的新 grantId 不会复活旧 Task。Native launch permit 与现有 250 ms revocation loop 仍是最后执行边界。权限未确认、state lock busy、store corrupt 均 fail closed。

声明 repository_path 的 execution step 要解析并锁定 canonical repository identity，child jobId 作为现有 repository lock owner；lock 仅在 child 运行期间持有。任意 host command 仍是 Full Access 操作，repo scope 只是协作锁，不构成 sandbox。

### MCP Tasks Extension Alignment

内部与协议解耦的层次固定为：PersistentTask Domain → C2C Task API Adapter（本版 proprietary task_* tools）→ future MCP Tasks Extension adapter。V1.4 只定义/实现 C2C adapter，不把 domain state machine 绑定到 @modelcontextprotocol/sdk 1.30.0 的 legacy experimental task wire format，也不在 A+B 同期迁移 SDK v2。

MCP Tasks Extension 的 tasks/get、tasks/update、tasks/cancel 与状态 working、input_required、completed、failed、cancelled 由未来 adapter 映射；标准没有 tasks/list。task_list 保留为 proprietary recovery/discovery API，用于 create 响应或对话丢失后的 owner 恢复。task ID 为 opaque/unguessable reference，但每次调用仍重新授权；workspace 与 owner OAuth client 双重隔离，列表有界，禁止跨 client 枚举。

### MCP API

- task_create(plan, idempotency_key) → taskId、状态和 plan hash；响应丢失后相同 key 可查重。
- task_status(task_id) → state/currentStep/completedSteps/totalSteps/fixed timestamps/lastCheckpoint/blockedReason。
- task_list(cursor?, limit≤20) → C2C proprietary recovery/discovery API；只列当前 owner OAuth client 在当前 workspace 的近期任务，不是标准 MCP Tasks Extension method。
- task_result(task_id, cursor?) → 结构化 step 摘要与有界结果页，单页≤64 KiB，含 next cursor 与 omitted/truncated。
- task_output(task_id, step_id, stream, offset, max_bytes≤64 KiB) → 委托现有 supervisor/job segmented output，保留 UTF-8 boundary 与 truncation metadata。
- task_cancel(task_id) → cancel request 与最新状态；不返回伪造百分比。

scope 映射复用既有 OAuth scopes：read-only plan 按 step 需要 workspace.read/search；execution step 要 execution.run；task read/output/list 要 execution.jobs.read；cancel 要 execution.cancel。无新增本机 permission tier。每次 API 请求重新验证当前 token、workspace、scope 与创建 Task 的 owner client；Task 结果仅向该 client 暴露。

## Risk Register

### P0

- **P0-A — Dispatch Ambiguity：** TaskStore 与 JobStore 没有跨-store transaction。每个 execution step 持久化 PREPARED → CHILD_BOUND → OBSERVED → CHECKPOINTED；stable child key 与 reconciliation 处理 crash window，unknown outcome 进入 WAITING_FOR_MODEL。
- **P0-B — Side Effects Not Exactly Once：** 不宣称 command execution exactly-once。准确承诺是 C2C prevents known duplicate dispatch and refuses unsafe automatic replay；已知或可能发生 side effect 时不得自动重放。
- **P0-C — Revocation Race：** 沿用 session fingerprint、grantId/ABA、authorization epoch、Native launch permit、runtime permission polling 与 Job Object cancellation；Task 层不创建第二套 authorization，状态不明时 fail closed。

### P1

- **Windows full-regression runner stability (residual):** A full `npm run test` regression invocation terminated with Windows status `0xC0000409` before a final aggregate test summary. Root cause remains UNKNOWN, and no C2C product bug is confirmed. Do not report the full regression as a clean PASS; this remains a test/runtime stability risk pending separate RCA.
- **现有搜索返回上限不是扫描成本上限。** V1.4 必须有文件/字节/deadline budgets，并测试被截断行为。
- **Repository lock 是协作锁。** Full Access host shell 可访问 cwd 外资源；声明 repository scope 不能伪装为 sandbox。Bridge crash 后未知 owner lock 维持 fail closed。
- **Secret sanitizer 是已知模式检测。** 敏感路径、private key 与常见 token 要拒绝或 redacted，但不能宣称识别所有秘密；package 每项标明 redaction/restriction 状态。

### P2

- **Batch snapshot cursor 仅驻内存。** Bridge restart 或 TTL 会使 cursor 过期；调用方重新 collect，使用 source hash 检查变化。持久长流程应使用 Task checkpoints。
- **Task Store 达到容量上限时需要明确拒绝。** 不自动丢弃 WAITING_FOR_MODEL、INTERRUPTED 或 side effect 未确认的任务。

## Wave3 Closure Fix: TaskStore Durable Commit

This addendum records the later Wave3 closure implementation; the Phase 0 status above is a historical snapshot.

Before dispatching an execution child, TaskStore serializes the complete bounded envelope to a unique sibling temp file, flushes the file handle, closes it, and publishes it through `durableAtomicReplace()`. The store updates its in-memory map only after that call succeeds. Write, flush, or publish errors remove only the exact temp path, fail the store closed, and prevent `ExecutionSupervisor.startFullAccess()` from running.

On Windows, durable TaskStore publication uses the existing integrity-checked Native helper. It opens the flushed temp file with `FILE_FLAG_WRITE_THROUGH`, calls `FlushFileBuffers`, and publishes that same handle with `SetFileInformationByHandle(FileRenameInfoEx)` using replace-if-present and POSIX rename semantics. The same path handles the first `tasks.json` publish and later replacements. It is enabled only on a local fixed NTFS volume and fails closed elsewhere. No `MoveFileEx`, copy/delete, PowerShell, or rename fallback is used. The existing ACL-preserving Native replacement also opens its source handle write-through.

On POSIX, TaskStore flushes the temp file, performs the same-directory atomic rename, then flushes the containing directory. A directory-flush failure is reported and blocks dispatch; the namespace operation may already have applied, so the store remains fail-closed rather than claiming rollback.

With the TaskStore directory hierarchy present on a local fixed NTFS volume, C2C guarantees durable-before-dispatch for the flushed TaskStore file contents and the `tasks.json` namespace publication under Windows write-through semantics. The write-through handle requests NTFS to flush rename metadata before returning. `ensureDir()` creates missing ancestor directories before Task persistence, but those directory creations are not independently synchronized through a POSIX-style directory flush. The implementation does not claim immunity to every storage-controller power-loss scenario. No physical power-loss hardware test was performed. A helper/process failure after publication but before its success response can leave the store outcome uncertain; that path blocks child dispatch, and Wave3 still stops an unknown PREPARED task instead of replaying it. Arbitrary external command side effects are not exactly-once.
